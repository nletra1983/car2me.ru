# Car2Me — генерация shortlist моделей

## Продукт

Информационный shortlist **моделей** (не лотов) под сценарии клиента. Каналы: **Япония, Корея, Китай** — только ввоз, без б/у с российского рынка.

**Не делать:** не звонить, не уточнять у клиента, не оценивать конкретные VIN/лоты (если не приложены отдельно).

**Срок:** один проход по ответам формы → отчёт за одну сессию.

## Входные данные

1. Экспорт **Яндекс.Формы** (`.xlsx`) в папке `Ответы/` — всегда полная таблица (старые + новые строки).
2. Очередь необработанных: `python scripts/responses.py pending --json`
3. Поля формы: [опрос-shortlist.md](../../../опрос-shortlist.md)
4. Опционально: ссылки на лоты, кейс `d:\Путешествия\кейс-подбор-авто.md`

**Не генерировать повторно:** обрабатывать только ID из `pending`. После отчёта — `mark` (см. ниже).

Если обязательных полей нет — **не генерировать отчёт**, перечислить недостающее (внутренне; клиенту не писать).

## Очередь ответов (incremental)

Яндекс отдаёт cumulative export. Уникальный ключ — колонка **`ID`** (например `2507760493`).

```
Ответы/
  *.xlsx              ← скачанный экспорт (берётся самый новый по дате файла)
  processed.json      ← журнал обработанных ID (локально, не в git)
Отчёты/
  {Имя}.md              ← как в поле «Как к вам обращаться?»
  {Имя}.pdf
  {Имя}-2.pdf           ← если имя уже занято
```

### Команды

```bash
# 1. Что ещё не обработано
python scripts/responses.py pending
python scripts/responses.py pending --json   # для агента

# 2. Один ответ целиком (все колонки)
python scripts/responses.py row 2507760493

# 3. Куда сохранить (имя = как клиент представился)
python scripts/responses.py suggest-path {ID} --name "Мария"
# → Отчёты/Мария.md · если занято → Мария-2.md

# 4. PDF после .md
python scripts/responses.py pdf "Отчёты/Мария.md"

# 5. Отметить обработанным
python scripts/responses.py mark {ID} \
  --md "Отчёты/Мария.md" \
  --pdf "Отчёты/Мария.pdf" \
  --email "..." --name "Мария"
```

**Авто-синхронизация:** если `Отчёты/{Имя}.md` существует и в frontmatter есть `car2me_response_id`, ID считается обработанным.

**Правило:** один ID → один shortlist. Повторная генерация только с `--force` в `mark` или после удаления записи из `processed.json`.

## Алгоритм

```
- [ ] 0. pending --json → если pending_count=0, стоп
- [ ] 1. row {ID} → профиль клиента
- [ ] 2. suggest-path --name «Как обращаться» → уникальное имя файла
- [ ] 3. Рассчитать веса → longlist → матрица → **кросс-проверки** → топ-3
- [ ] 4. Сохранить Отчёты/{Имя}.md (frontmatter: car2me_response_id)
- [ ] 5. python scripts/responses.py pdf "Отчёты/{Имя}.md"
- [ ] 6. mark {ID} → следующий pending
```

### Шаг 1. Профиль клиента

Извлечь явное и из свободного текста:
- Сценарии + частота «сложного» (для текста отчёта, не для весов)
- **Топ-3** «без чего не подойдёт» (стр. 3)
- **Матрица критериев** — 16 вопросов «один вариант» с важностью (стр. 3)
- Бюджет под ключ + жёсткость
- Город / климат
- Каналы (KR / JP / CN; «серый» — только если согласен)
- Руль, коробка, двери, размер, пассажиры
- Табу и пожелания своими словами
- Прямой вопрос для отчёта (если есть)

### Шаг 2. Веса от клиента

**Источник весов — ответы клиента, не эталонный кейс.**

1. Из 16 вопросов «Насколько важно: …» (стр. 3): Не важно=0, Желательно=1, Важно=2, Критично=3.
2. Бонус +0.5 к связанным критериям за каждый из **топ-3 сценариев** (таблица в [criteria-weights.md](criteria-weights.md)).
3. Нормализация: `weight[c] = score[c] / Σscore × 100`.

Если Σscore = 0 — не генерировать отчёт.

**В отчёте показать клиенту** три списка приоритетов (критичные / важные / желательные) + топ-3 сценария — без таблицы весов.

Hard filters (не веса) — из рамок и техники:
- Только левый / lhd=Критично → RHD out
- Только автомат → MT out
- ≥5 дверей → 3-door out
- До 160 л.с., избегать DCT, табу-марки, серый parallel «нет», Китай «нет»

Свободный текст → filter или ручная корректировка: «не CVT», «не 1.6 Turbo Encar».

Подробности: [criteria-weights.md](criteria-weights.md)

### Шаг 3. Longlist

Стартовый пул по каналам клиента:

- **KR:** Creta, Seltos, Kona, Soul, Tucson, Sportage, Casper, Stonic…
- **JP:** Raize/Rocky, Rush/Terios, Vezel/HR-V, Fit, Yaris Cross, CX-3, XV, Suzuki Escudo/Vitara…
- **CN:** Haval Jolion/H6, Chery Tiggo 4/7, Geely Coolray, Jetta VS5, Omoda…

Исключить сразу:
- Каналы вне JP/KR/CN
- Серый parallel (BYD, Zeekr…) если клиент сказал «нет»
- 3-door, если нужно ≥5 дверей
- Моторы/КПП из hard filter клиента

Для каждой модели указать **версию** (мотор + коробка), не только название: «Seltos 1.6 AT» ≠ «Seltos 1.6T 177 Encar».

### Шаг 4. Бюджет под ключ

Оценка «под ключ» ≈ лот + **750–950 тыс. ₽** (KR/JP/CN, брокер, пошлина, утиль).

Источники (проверять актуальность):
- Encar (KR): цена в ₩, грубо ÷1000 × 60 ₽ + доставка
- JP аукцион: tokidoki, vladdiler, шаблоны брокеров
- CN: Drom, объявления parallel/official

**Честность важнее рейтинга:** модель с высоким баллом, но вне бюджета → статус «не влезает в деньги» + реальная вилка.

### Шаг 5. Оценка и статусы

По каждой модели: балл /100 (взвешенная сумма), оценка 1–5 по ключевым критериям.

| Статус | Условие |
|--------|---------|
| **Лидер** | Топ по баллу + бюджет ок или «на грани» при мягком лимите |
| **В списке** | Балл ≥75% от лидера, осмысленный компромисс |
| **Осторожно** | Есть, но существенный минус под сценарий или бюджет на грани |
| **Не рассматривать** | Hard filter / явно не под сценарий / нет на рынке |

Таблица **типичных минусов**: мотор, коробка, кузов, комфорт, «критично не брать» — со значимостью (высокая / средняя / низкая) **для сценариев этого клиента**.

### Шаг 5.5. Кросс-проверки (обязательно)

**Не пропускать.** Подробный чеклист: [cross-checks.md](cross-checks.md).

Минимум перед сохранением отчёта:

1. **Возраст × рынок** — типичный год лота на канале не старше лимита клиента (поле «Максимальный возраст» или «слишком старое» из текста).
2. **КПП × поколение × рынок** — не обещать AT, если у допустимого по возрасту поколения на этом рынке только CVT (типичная ошибка: **Honda Fit CN 2021+**).
3. **Мотор × табу** — атмосфер vs турbo, «китайские с вариаторами», Encar-ловушки.
4. **Бюджет × версия** — вилка цены для **той** версии (год + КПП + комплектация), которую рекомендуете.
5. **Статус × конфликты** — при hard filter статус не «Лидер»; конфликты — в блоке «Где критерии конфликтуют» или в «Компромиссы».

Если модель не проходит кросс-проверку — понизить статус, убрать из топ-3 или исключить **до** записи `.md`.

**Именование файлов:** поле «Как к вам обращаться?» → `Отчёты/Мария.md` и `Отчёты/Мария.pdf`.  
Если `Мария.md` или `Мария.pdf` уже есть → `Мария-2`, `Мария-3` … (`suggest-path` / `allocate_report_paths`).

**Frontmatter** (для очереди, не для клиента в PDF):

```yaml
---
car2me_response_id: 2507760493
---
```

**PDF:** после сохранения `.md` всегда:

```bash
python scripts/md_to_pdf.py "Отчёты/{Имя}.md" "Отчёты/{Имя}.pdf"
# или
python scripts/responses.py pdf "Отчёты/{Имя}.md"
```

Скрипт: `scripts/md_to_pdf.py` (Chromium через Playwright). Стили и колонтитул — только там; при смене вёрстки править скрипт, не inline в каждом отчёте.

**Ориентация:** `<!-- pdf: landscape -->` сразу после frontmatter — альбомная A4 (матрица, риски). Без маркера — портрет.

**Дисклеймер:** не секция в `.md`. Добавляется автоматически колонтитулом Playwright на каждой странице (`display_header_footer`). Не использовать `position: fixed` в CSS — контент будет заезжать под футер. Текст дисклеймера — `DEFAULT_DISCLAIMER` в `md_to_pdf.py`.

### Правила вёрстки (обязательно)

| Правило | Почему |
|--------|--------|
| Заголовки внутри `<div>` — **HTML** (`<h2>`, `<h3>`), не markdown `##` | Иначе `##` выводится как текст |
| Первая страница — **вертикальный стек**: профиль → приоритеты → словарь | Не `two-col`, не `margin-top: auto` у словаря |
| Матрица — только HTML в `.matrix-section`; «Коротко» и конфликты — в `.matrix-tail` | Хвост на новой странице, не под таблицей |
| Ячейки критериев: `<div class="score-cell"><span class="score-val">5</span><span class="score-note plus/minus/neutral">…</span></div>` | Единый стиль с рисками |
| **Без цветного фона** строк матрицы | Фон только у бейджей в таблице рисков |
| Новые разделы — `<h2 class="page-break">` | Матрица, риски, топ-3, компромиссы, Q&A — с новой страницы |
| Блоки `###` (комментарии, Q&A) | Скрипт оборачивает в `.model-block` — не рвать заголовок от текста |
| Жирный в комментариях / компромissах / Q&A — **только метки структуры** (`**Почему в топе:**`, `**Компромисс A — …**`, `**Рекомендации по вождению:**`) | Не выделять каждое число и модель |

**Эталон:** `Отчёты/Ната-тест.md` + `Отчёты/Ната-тест-v7.pdf`.

**Рекомендации по эксплуатации (обязательно при компромиссах):**

Если модель или опция **не полностью совпадает** с критерием клиента — добавить **рекомендации по вождению** и **когда лучше отказаться**.

```markdown
**Рекомендации по вождению:** … (манера, маршруты, нагрузка)
**Лучше отказаться, если:** … (когда компромисс не спасает)
```

### Шаг 7. Качество

- **Язык:** по-русски. Не подменять русские слова английскими (*dramatically*, *vs*, *grade* как обычное слово и т.п.). Допустимы: марки и модели, RHD/LHD, AT/CVT/4AT/6AT, Encar, VIN, ESP, TSS, обозначения комплектаций (G/Z), 4WD.
- Язык для клиента: **без жаргона**; AT/CVT/DCT/л.с. — только с расшифровкой.
- Не «всё хорошее» — честные «не влезает», «осторожно с …».
- Каждая модель в shortlist: **зачем в списке** и **от чего отказаться**.
- Упоминать **конкретные версии** мотор/КПП где это ловушка (Seltos 1.6T, Kona 1.6T 177, **Fit CN 2021+ = только CVT**…).
- **Кросс-проверки обязательны:** [cross-checks.md](cross-checks.md) — возраст × рынок, КПП × поколение, бюджет × версия.
- **Факты:** RHD/LHD **текущей** машины клиента — проверять (Polo в РФ = LHD). Не писать «привыкли к правому на Polo» и т.п.
- **Компромиссы и Q&A:** при несовпадении с критерием — **«Рекомендации по вождению»** + **«Лучше отказаться, если»**. См. [cross-checks.md](cross-checks.md) § «Эксплуатация при компромиссах».

## Примеры фильтров из текста

| Фраза клиента | Действие |
|---------------|----------|
| «не хочу правый руль» | RHD → out или «осторожно» |
| «не CVT» | CVT-модели ↓ или out |
| «не 1.6 Turbo Encar» | hard filter Seltos/Kona turbo KR |
| «спал(а) в машине на Байкале» | проверить sleep_in_car в матрице; если низко — упомянуть в отчёте |
| «сгорел мотор» | проверить engine_reliability; filter turbo при «критично» |
