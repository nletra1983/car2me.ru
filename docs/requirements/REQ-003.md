# REQ-003 — Пользователь принимает куки

**Статус:** draft  
**Контур:** mixed — UI баннера as-is; связь с Метрикой — gap (код ≠ privacy)

> Проверить с юристом. Единая правда с [REQ-002](REQ-002.md).

## Предварительные условия

У пользователя нет сохранённого выбора согласия для этого сайта (`localStorage`, ключ согласия аналитики).

## Поведение

### As-is (код)

- Пользователь переходит на сайт
- Пользователь видит баннер о cookie с вариантами «Принять» и «Только необходимое»
- До взаимодействия баннер виден; после выбора — скрывается, выбор сохраняется
- **Яндекс Метрика при этом уже загружена** при открытии страницы (баннер сейчас не блокирует загрузку счётчика)

### Target (как заявлено в `privacy.html`)

- Счётчик загружается только после «Принять»
- «Только необходимое» / игнор баннера — без аналитического счётчика (или иной режим, который подтвердит юрист)
- После выбора баннер исчезает

## Acceptance criteria

- [ ] Логика cookie и аналитики не противоречит закону РФ (заключение юриста)
- [ ] Код, политика ПДн и REQ-002/003 описывают **одну** модель (нет расхождения «Метрика всегда» vs «только после Accept»)
- [ ] Баннер: до выбора виден; после «Принять» или «Только необходимое» — скрыт, выбор запоминается
- [ ] Поведение Метрики после выбора соответствует согласованной модели из REQ-002
